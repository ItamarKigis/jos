=== Q The break point test case will either generate a break point
===   exception or a general protection fault depending on how you
===   initialized the break point entry in the IDT (i.e., your call to
===   SETGATE from idt_init). Why? How did you need to set it in
===   order to  get the breakpoint exception to work as specified
===   above and what incorrect setup would cause it to trigger a
===   general protection fault?
===   (free form)
whether breakpoint test generate a breakpoint exception or a general protection fault depends on the DPL field in the IDT descriptor that corresponds to breakpoint. if the DPL field is 0, invoking breakpoint from user mode (CPL = 3) will generate a general protection fault since CPL > DPL. to get the breakpoint exception, we had to set the DPL of its descriptor to 3 in the SETGATE macro.
An incorrect setup would be setting its DPL to 0 instead of 3 which will cause a general protection fault as we've explained, i actually did this mistake while solving this lab and it took me some time to understand why!

in kern/trapentry.S:
i changed  the TRAPHANDLER macros to write the handler address to data section by adding
.data
    .long name
to the macros. I also had to put a .text label at the beginning of the macros to make sure they switch back and forth when being used in succession.
in addition, i've set a label called trap_table at the data segment so it could be later referenced in the c code.

in kern/trap.c:
using trap_table automatically generated by the macros, i could loop over it and use a single SETGATE pointing to trap_table[i] for each handler.
This loop sets all interrupts to DPL=0, so i had to manually use SETGATE again with DPL=3 for breakpoint and syscall, which required a few extra lines, but overall it saves a lot of code lines compared to the original implementation.
